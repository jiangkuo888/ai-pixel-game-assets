# 运行时排查

查实际工程的导入与渲染设置；需要版本相关 API 时看官方文档，不把此清单当作最新 API 文档。

| 症状 | 检查与修复 |
| --- | --- |
| PNG 清晰，游戏模糊 | nearest/point 过滤；Canvas backing store 与 CSS 尺寸；先渲染逻辑画布，再统一整数放大 |
| 同尺寸 PNG 主体忽大忽小 | 核对主体 bbox、世界尺寸、PPU、基线；按参考物配准，不逐张拉满 |
| nearest 后颗粒仍不同 | 检查混合粗细网格、内部大色块、预先 2× 放大的图片和不同世界倍率；修复源或逻辑分辨率 |
| 移动闪烁 | 亚像素相机/位置、非整数倍率；模拟可保留浮点，最终呈现按工程策略对齐像素网格 |
| 动画跳动 | 自动 trim、逐帧 pivot、脚底；共享画布、稳定 pivot，保留 atlas trim offset |
| 图集串色 | padding、边缘 extrusion、UV；通常关闭 mipmap 与有损压缩，确需远景缩小时另定策略 |
| 透明边缘黑/白晕 | alpha 预乘约定、透明像素 RGB 与线性混合；在浅/深背景检查，不用阈值草率删边 |
| 小屏幕细线断裂 | 非整数缩小、源线宽、采样相位；保持逻辑画布整数倍率，必要时重新设计轮廓 |

Web：关闭发生 `drawImage` 缩放的上下文 smoothing；改变 canvas 尺寸后重新设置。CSS `image-rendering: pixelated` 不能修复已模糊写入的 Canvas。DPR/浏览器缩放会使 CSS 整数倍不等于物理整数倍；严格模式按设备像素选倍率并留边，不单轴拉满容器。

引擎：统一 texture filter、sprite PPU 与相机投影，检查导入阶段是否重缩放；旋转/倾斜或连续缩放需说明严格像素网格的取舍。

验证原生尺寸、同场景混摆、运动/动画及目标屏幕尺寸。记录资源自动检查、视觉检查、游戏内检查三个独立状态；没有工程就只交付导入建议。
